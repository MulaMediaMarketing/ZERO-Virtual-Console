# ZERO Player Security Policy

## Supported production surface

Security support applies to the current **ZERO Core V5 Windows 11 x64** production surface and to exact production releases generated by the production-release pipeline.

Online commerce, ZERO ID, ZERO Link/social, ZERO Cloud, remote content delivery, DRM, anti-cheat, native video encoding, public publisher PKI, ARM64, and non-Windows targets are not represented as deployed production services until separately implemented and qualified.

## Reporting a vulnerability

Do not publish exploit details in a public issue before coordinated remediation. Report suspected security vulnerabilities privately to the repository owner through an approved private communication channel.

Include, where possible:

- affected commit/release;
- component and attack surface;
- reproduction prerequisites;
- minimal reproduction steps;
- expected vs observed security boundary;
- crash dump or diagnostics with credentials/tokens removed;
- whether integrity, trust, IPC, package paths, persistence, installer/update, signing, or online authority is involved.

## Security invariants

A security fix must preserve these invariants:

- malformed or untrusted package metadata fails closed;
- package files are integrity verified before launch;
- managed publisher trust requires successful ECDSA P-256/SHA-256 verification;
- runtime IPC requires the authenticated local session contract;
- package paths remain contained under validated roots;
- player data remains separated from replaceable program files;
- destructive/install/update operations are transactional or recoverable;
- authoritative online/commercial state is never minted by the Windows client;
- one authority exists for each production concern;
- UI code may project authority but may not become an authority itself;
- production artifacts require exact-commit physical qualification plus valid Authenticode signing;
- release evidence and SBOM are bound to the exact candidate commit.

## Online/service authority

The Windows client fails closed when a service is disconnected or unverifiable.

Server-owned truth includes:

- ZERO ID sessions and account authentication;
- Store catalog publication, pricing and checkout quotes;
- managed entitlements;
- friends, blocks, presence, invitations, parties and join authorization;
- cloud saves and cloud session allocation;
- managed remote devices;
- global achievements/score where configured as server-authoritative;
- publisher enrollment/revocation and moderation/security verdicts.

Local caches and UI state must never be promoted into these authorities.

## Remediation requirements

Security-sensitive changes require hostile-input/regression coverage, Windows Build PASS, CodeQL PASS, production architecture PASS, and requalification when the change affects runtime, shell, SDK, installer, manifest, signing, packaging, service authority, or hardware-observable behavior.

See `docs/ENGINEERING_START_HERE.md`, `docs/PRODUCT_ARCHITECTURE.md`, and `docs/ZERO_CORE_ARCHITECTURE_V5.md` for ownership and dependency boundaries.
